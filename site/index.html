Yantra What it is like Source

Your tasks are files you own.

Yantra is a todo app whose notes are as good as a notes app's. Everything you write is plain Markdown in a git repository you control — not a database you can only reach through us.

The rule everything follows

One loop, and nothing is allowed to block it.

The spine is a task list, and the whole app is judged on capture → triage → do. Notes, drawings, the calendar and the timer are all in service of that loop rather than competing with it. Capture in particular is never blocked: what you type is parsed for dates, labels, priority and a list, and it lands whether or not the parse understood you.

Offline first

It runs entirely on the device. There is no account until you choose to point a workspace at a repository, and no Yantra server at any point.

Plain Markdown

A directory of ordinary files. If the app went away tomorrow you would still have everything, readable in any editor.

Sync is git

Each workspace is a repository of Markdown on a yantra-tasks branch. Commits are batched by policy; conflicts are rebased and arbitrated.

What it is like to use

Six moments, from the app itself.

Home is every list you have

Each row counts only its tasks — the events on a page are not tasks and are not counted, and an archived task has left the list, so it is not counted either. The ring closes as a list is finished.

A list, and a page for anything on it

Every task can open into a page of its own: prose, subtasks, links to other tasks, images and ink. That is what "notes as good as a notes app's" has to mean to be worth saying.

A day you can put things on

The day is a ruler with your tasks and events on it. Pick a task up from the rail and tap an hour to place it; drag a block to move it; swipe the day itself to reach yesterday or tomorrow.

Focus is a ledger, not a timer

Every session is written down start to end with how it ended — finished, interrupted, ran out — and survives the process being killed. A clock you cannot account for afterwards is not worth starting.

Ink is stored as ink

Each stroke keeps its own input points — position, time, pressure, tilt, orientation — in a portable envelope, on a document that is a stack of pages rather than a screenful. It is drawing on paper, not a picture of a drawing.

And what it added up to

Because every session was persisted rather than counted, the stats screen is reading a ledger. It can be wrong only if the ledger is.

^id is the task's identity, which is what lets two devices agree about the same line. [~] is in progress. @ is an event. Nothing here needs Yantra to be readable.

And the first line of it is a page too.

^demo-chapter above is a task. It is also a file. Open the task and you are in it, and what you write there can be prose, a drawing, or more tasks — which have pages of their own, as far down as the work actually goes. A subtask here is not a lesser kind of thing with fewer rights: it is a task, with its own due date, its own notes and its own inside.

parent: is the line it came from. That is the whole of the nesting: a task that holds work is a page, and a page is a file.

Other people's meetings

Their meeting, your page.

A meeting in your device calendar belongs to whoever sent it. You cannot make it yours, and a calendar you can only look at is a calendar you cannot prepare for. Tap one in Yantra and it makes you a page for it — in your inbox, holding a reference to the original — so the notes and the tasks you put on it are yours. Tap the same meeting tomorrow and it is the same page, with what you wrote still on it.

A repeating meeting gets a page per occurrence rather than one page for every Monday, because a page about this Monday is not a page about all of them.

Working with someone

Sharing a list is sharing a repository.

There is no invite flow to learn, because there is nothing of ours to join. A workspace is a git repository, so you share one the way you share code: add them as a collaborator on GitHub. They point Yantra at the same repository and both devices are working on the same files.

Assignment then works off that repository's own roster. @ offers the people actually on the repo rather than a free text field, because a task assigned to somebody who cannot see the repository is a task nobody will ever be shown — and the app knows who can see it at the moment of the tap. Their changes arrive the way code does: as commits, rebased and arbitrated.

Where your writing goes

Nowhere, unless you send it somewhere.

Yantra collects nothing. There is no Yantra server, no account with us, no analytics and no third-party SDKs — nothing you write is sent to us because there is nowhere for it to go.

If you turn sync on, your files are pushed to a git repository you own, with a token you granted, and the traffic goes from your device to GitHub without passing through us. On Android that token is sealed with a Keystore key that never leaves the phone.

Deliberately not done

Things it does not do, on purpose.

  • Not built for a team editing at once. You can share a repository and assign work on it, but the conflict arbitration was written for one person on several devices. Two people editing the same line at the same moment is not a case it claims to be good at.
  • No arbitrary filter editor. Smart lists are created from the builder's templates. The underlying JSON model supports more than the interface offers, and that is the intended trade.
  • No canvas mode. The schema carries the coordinates for one and nothing reads them yet.
  • No account, no cloud of ours. Not a feature that is coming; there is deliberately nothing to sign up for.

Where it actually is

Not released yet.

Android is the complete app and the one the design is defined by. It is not on Google Play; it builds from this repository with ./gradlew :app:assembleDebug.

iOS is being brought to parity with it and is not finished. It is not on the App Store. Several areas are still missing — some widgets, lasso selection in ink, parts of the sync interface — and the repository's own notes track what is left.

If you want to try it, build it. If you want to judge it, read it.
